# NPB Player Directory

The NPB Search screen reads `data/npb/players/latest.json` from GitHub Pages. A manual, independent `npb-player-directory-publish.yml` workflow reads the existing Turso `master_history` for canonical Player and Team identities and reads distinct Player IDs from batting and pitching Fact tables for availability. It uses five SELECT queries regardless of Player count. No source website is accessed and no Fact or derived DB row is written. The directory contains every validated Player Master row, including Players without Game Facts; it is not a roster backfill or an assertion that all active NPB Players are present. The currently ingested Player Master is largely Fact-derived.

Schema version 2 contains an effective date, separate generation timestamp, 12 Teams and Players with canonical ID, display name, current stored Team, optional verified position, birth date/place, nationality, separate batting/throwing hands, and batting/pitching/recent Fact availability. Position and hands are null when not verified. No name reading, romanization, image, nf3 ID/URL, raw response or credential is generated. The client validates the complete JSON and retains a last-successful copy locally if the endpoint later fails. A fresh query to Turso is never made for typed search text; normalized Japanese display names are ranked exact, prefix, then partial, with a stable ID tie-break. Spaces and width differences are ignored. Team and Fact-role filters operate on the same downloaded array. An absent Player Fact does not remove the Player from the directory or prevent navigation to the no-data Recent state.

## Verified Player Master v2

The canonical Player ID remains the existing UUID. `master_history` is the independent Player Master; `source_entity_mappings` maps external IDs to it. Fact tables only add availability flags. No schema migration or Fact mutation is needed. The manually reviewed links in `src/data/npb-verified-player-mappings.ts` bind four Wikidata entities to three existing canonical Players and one new no-Fact Player. Each link records name, 2026 Team, birth date, optional position, and a review reason. Name alone can never match or create a Player. The importer rejects a changed Wikidata name/team/birth date/position, duplicate external mapping, same-name existing candidate, existing canonical identity conflict, and same-day non-Wikidata master conflict before its batch write. Re-running the reviewed import is idempotent. Manual review should precede any new mapping; no broad roster or Wikidata search is automated.

The bounded provider requests four reviewed Wikidata entities and their birthplace/citizenship labels, not a roster crawl. Wikidata structured statements are CC0; Wikimedia article text and photographs are not copied. Only fields actually present in the statements are stored. Internal profile provenance tracks the source ID and verification timestamp by field. Existing canonical name and Team take precedence over Wikidata and are never overwritten on disagreement; a conflict blocks that Player's import rather than publishing a guess. The Master keeps the current stored Team separately from each historical Game Fact Team. Batting and throwing hands are null because they are not in these Wikidata statements. Position is only mapped for known pitcher/catcher entity IDs; an unknown or broad value is not converted to a detailed field position. Neither Wikidata ID nor provenance/debug details are shipped in the public JSON.

To update the reviewed Master, dispatch **Publish NPB Player Directory** with `import_verified_profiles=true`. That opt-in stage validates the four identities, applies the Master and source mapping batch to Turso, then regenerates and publishes the version 2 Directory. Without that input, the workflow remains read-only. The static JSON combines the small search Directory and basic Profile so a Player page needs no per-Player Turso query; Recent stats still come from the existing period service. The `data/npb/players/latest.json` URL is unchanged. The Player Header omits unverified fields, and a Player without Facts shows `最近の成績データはありません`. Position filtering and kana search remain deferred because verified coverage/readings are insufficient.

To publish, dispatch **Publish NPB Player Directory** on `main`. The job generates and validates the JSON, stages current standings and the previously published validated HOT JSON, builds the full Pages artifact, then checks the actual public directory HTTP response after deployment. Pages deploys replace the whole site, so the Daily and HOT **delivery steps only** also preserve the last valid Player Directory payload. Neither workflow generates a new Directory or changes collection. The three Pages workflows share one concurrency group. If a previous directory is unavailable or invalid, preservation skips it; the Search screen shows a local fetch error until the directory is manually published again.

This is intentionally manual while the Daily Collector's unattended full-day run is under separate verification. Future automation may refresh the directory after a successful ingestion, but no new cron is enabled here. The search UI is NPB-only; MLB retains its existing sample discovery screen. Position filtering is deferred until trusted position metadata is stored. Display-name sorting is **not** labeled as Japanese gojūon order because reading metadata is absent. Team association is the latest stored Player Master value, so historical team affiliation is not inferred.

The first [manual directory publication](https://github.com/tomoya41/baseball-notes/actions/runs/36207257502) succeeded on 2026-09-26. Remote output for effective date 2026-09-25 contained 12 Teams and 288 Players (234 with batting Facts, 107 with pitching Facts, zero without either); the overlap includes Players with both types of Fact. Five DB reads took 1,175 ms, total generation 1,182 ms, and the JSON was 51,394 bytes. A cache-bypassed public HTTP fetch returned 200 in one observed 499 ms request. Searching 288 Players for `坂本` averaged 0.587 ms over 1,000 local iterations. The published payload contained no source IDs/URLs or credential fields. Public standings (12 Teams) and HOT (still `not_ready`, empty rankings) survived the whole-site deployment. The public Search screen found and linked 中島大輔, 上原健太 and 坂本誠志郎 by canonical ID, including an input with a name space; their existing Recent views loaded without error. Since the current Master is populated from collected participants, no Player without a Fact exists in production yet, although the schema and UI handle that case in tests.

The [reviewed v2 import and publication](https://github.com/tomoya41/baseball-notes/actions/runs/36209364998) succeeded later on 2026-09-26. It retained all 288 existing canonical Players, added 早川隆久 with an independent canonical UUID and no Game Fact, and linked four reviewed Wikidata source IDs. The v2 JSON has 289 Players, 12 Teams, one no-Fact Player, three known positions, four birth dates, three birth places, and zero verified batting/throwing hands. No duplicate display-name candidate appeared. Five Directory SELECTs took 618 ms and total generation 628 ms. Public HTTP returned 200 for the 86,626-byte version 2 JSON; the no-Fact Player appears in Search and opens the canonical Player screen with profile and no-data Recent. The 2026-09-25 effective date is the standings date, not the profile verification time.

The [second reviewed import](https://github.com/tomoya41/baseball-notes/actions/runs/36209741108) also succeeded: 289 existing canonical Players, zero new Players, four existing profiles reviewed, four unique Wikidata mappings, and zero duplicate source IDs. The import's before/after checks found unchanged Game data (384 batting Facts, 120 pitching Facts, 35 Games). The republished payload remained 289 Players and 86,626 bytes; public HTTP returned 200. At 360px, the published Dark and Light Player views showed verified profile fields without a long header. Search for 早川隆久 linked to the canonical Player URL, where Recent showed the explicit no-data message with no mock fallback. 中島大輔, 上原健太 and 坂本誠志郎 also displayed their verified fields in the public Player view.
