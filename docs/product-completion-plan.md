整理日：2026-10-28。基準main：`47e1140ccb83df1a78d3100eb5284caea3c80325`（PR #97まで）。**製品要件の正本は [SPEC §0](../SPEC.md#completion-baseline)**。この文書は実施順、現在確認できる範囲、不足証拠を管理する。新機能の実装、Source取得、DB診断、AI呼出し、端末・署名・ストア操作は今回行っていない。

## 読み方と状態

- R01–R12はSPECの本体要件、J01–J07は一連の体験の受け入れ条件。IDの意味・完成条件はSPECへ集約し、ここで別の定義を作らない。
- 状態は「未着手 / 実装・接続中 / 検証待ち / 外部依存で保留 / 宣言した範囲で完了」。同じ要件に複数の状態がある場合は、できた範囲と不足を併記する。
- 以下は既存コード・pin・日付付き資料から確認した整理。Production DBの最新readbackや全機能の新しい実測監査ではない。過去の150項目の完成率を現在値として使わない。
- 本体の未完了と、利用条件が成立していない条件付き拡張を分離する。機能名の変更や対象の縮小だけで完了にしない。独立して進められる作業は保留しない。

各行は作業領域であり、一つの巨大PRにまとめない。開始時に最新main・既存実装・Source/権利・対象範囲を確認し、一つの計算/導線/契約/運用修正としてレビュー・検証・revertできる単位へ分ける。今回は文書整理までで、下記機能へ自動着手しない。

## 保留の記録と再開条件

| 保留の種類 | 必要な証拠 | 保留中も進めること |
|---|---|---|
| データ/本人照合/完全性 | 明示ID、独立した本人情報、対象母集団、欠損の理由、検証できる成分 | 既存採用データでの集計・導線・部分範囲の明示。曖昧な人名やゼロ補完で解消しない。 |
| 取得/公開権利 | 公開された正式条件、確認日、取得/保存/加工/Web/Android/再配布ごとの適用範囲 | 許された代替Sourceと既存adapter、未収録の正確な状態。Source名やクレジットだけを許諾と扱わない。 |
| Turso | 通常実行で実際の復旧・負荷・収集/公開証拠 | 最後の検証済み公開データと独立した分析。追加probeや別アカウント・課金で突破しない。 |
| AI品質/無料枠 | 構造化出力、参照照合、日本語品質、実試行/入力hash/消費量 | 決定論的な統計・説明。未採用を正式採用へ変更せず、失敗の再試行枠を復活させない。 |
| 所有者・端末 | 実端末/認証、正規鍵、owner/contact、署名証明書と配信環境の実証 | 安全な診断・手順・unsigned準備。秘密鍵の復元を装わず、データ削除や署名差替えをしない。 |

通知・写真・ロゴ・正式配布の条件はplatform/素材単位で確認する。PWAの更新成功をnative本体の更新互換性や背景Pushの成功へ転用しない。

## 各レビュー単位に残す受け入れ記録

以下はチェック項目であり、現在のPASS表ではない。

- 対象のR/J ID、対象外、既存実装との差分、宣言した提供範囲。
- 実データのSource/改版・identity・rights・Coverageと、不足/保留理由。
- 実際の利用経路、対象期間・母数・null/partial・訂正の検証。
- 個人保存、旧URL/Deep Link、ID、immutableデータの保全とrollback。
- 必要なテスト・lint/typecheck・Web/Vercel/Android build・実画面/端末結果。未実施や旧版の結果を今回のPASSへ読み替えない。
- 新規画面なら生成した参照画像と、既存UI・実画面との比較。文書だけで生成済みにしない。
- 更新/通信/容量/キャッシュ/DB負荷・追加費用、公開範囲と実際の公開後確認。
- 未達の完成条件、外部依存、具体的な次の証拠。Sourceなしの空画面や予約schemaの追加だけで閉じない。

今後の完了報告は、宣言した範囲で閉じたR/Jと未達条件を示す。「PRをマージした」「テストが通った」「公開できた」だけでアプリ全体完成とはしない。
