# NPB Player Analysis: opponent (30 calendar days)

The opponent split reads only saved Player Game Facts joined to canonical Games. It uses the same situated-Fact query and classifier as Home/Away: the Fact's historical `teamId` must match exactly one Game team, the two Game team IDs must be distinct, and a stored Fact opponent must not conflict. All other rows remain `unknownOpponent`; a player's current team or a team name never determines an opponent.

The application groups classified rows by canonical opponent team ID and passes each group to the existing batting or pitching period aggregator. The `30d` resolver, metric availability, and Period Coverage are shared with Recent and Home/Away. Zero-PA appearances, zero-out appearances, and separate same-day games remain in their groups. The response contains aggregate results and unknown counts, not raw Facts. `classifiedTotal` covers only rows with a verified opponent, so its counting stats equal the sum across opponent groups. Coverage describes the full 30-day collection history, not the opponent sample.

The Player Analysis screen keeps the 7/14/30 comparison and Home/Away above the opponent section. A 30-day opponent selector lists only teams with classified Facts, in the existing Team display order; its default is the latest played opponent, with that display order breaking same-day ties. One team is displayed without a dropdown. Rates and sample are shown without relative-strength labels or rankings. The comparison column is the classified 30-day total, and unknown rows are disclosed separately. WHIP is never shown.

The opponent endpoint is independent of Home/Away so a failure in one section does not hide the other. It makes a fixed number of read-only queries regardless of opponent count; currently each endpoint reads the same 30-day Facts separately. This small duplicated read preserves independent loading/error behavior without a shared browser cache or a larger API migration. Other periods can reuse the grouping flow when explicitly requested. No Derived data is stored.
