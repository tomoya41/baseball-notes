## Research method and decisions

Viewed official/public browser screens and images. Native competitors were **not installed**; no device benchmark, private API, statistical acquisition or third-party asset copying was performed. These observations concern presentation. Exact native font sizes cannot be measured from promotional screenshots; hierarchy/density comparisons are qualitative.

The chosen interpretation is **Sports Broadcast × Scouting Report**: opposing scores and decisive numerical hierarchy for games; names and role-specific stats for profiles; editorial rank treatment for HOT; restrained rows and transparent samples for analytics. A retained scorebook/journal layout was considered but rejected because ruled sections without different priorities would repeat the previous UI's weakness. A photo-led magazine layout was rejected because portraits/logos are not rights-cleared in the existing contract. No confirmation is required to choose a design: the user's current request explicitly delegates this decision.

After the user's additional visual-material instruction, the experimental decorative field SVG was removed. Navigation/actions use the existing Lucide set. No custom decorative icon set, raster backdrop, external font, unknown-rights photo or large initial-only Player hero is added. Scores, real stats, names, restrained surfaces and useful comparison bars carry the visual identity.

## Engineering and release boundaries

`styles.css` owns tokens, reset, shell and shared interactions; `feature-layouts.css` retains necessary feature layout contracts without old shared overrides; `final-design.css` owns dedicated screen compositions. Old repeated token/shell layers are removed rather than appending another override sheet. No new runtime dependency or font request. Presentation primitives share formatting/domain calculations; no duplicate statistical engines.

No source, collector, schema, canonical database, public data, capability or gate is changed. Favorites, Collections, Saved Views, Activity and Watch remain in their established application boundaries. Same hash URLs, five primary destinations, native Back, correction-aware readers and offline indication remain. Reverting the UI commits restores presentation without a data migration.

Measured delivery, screenshot evidence, final review and deployment results are recorded in `astra-reconstruction-delivery.md` when verified. Hardware Android, TalkBack, truly disconnected-device startup, signing/App Links and Play remain manual release gates.
