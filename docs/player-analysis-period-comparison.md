# NPB Player Analysis: recent period comparison

The canonical NPB Player Analysis section compares **7, 14, and 30 JST calendar days** ending on the latest saved NPB standings date. It reads saved Player Game Batting and Pitching Facts only. The existing period resolver, batting/pitching aggregators, metric status, and Coverage Calendar determine every value. This is a read-only derived view; no analysis table or snapshot is written.

`GET /api/npb/analysis?playerId=<canonical UUID>` returns the three periods together. One read checks Player Master identity, two range reads fetch up to 30 days of dated batting/pitching Facts, and three reads fetch shared day/game Coverage evidence. The endpoint also reads latest standings to select the same `asOfDate` as Player Recent. It does not access nf3 or a Season Total page. Each period is filtered by its inclusive date window before calling the existing aggregators, so a corrected Fact appears on the next read and same-day doubleheaders remain separate Facts.

The UI shows OPS, AVG, OBP and SLG for batters; ERA and K/9 for pitchers. Each period also shows its sample: PA, H, HR, BB and SO for batting; appearances, IP (formatted from integer outs), BF, H, HR, SO and ER for pitching. Metrics with `partial` or `unavailable` status display `—`. Period Coverage is shown separately for each window. Numeric values may be available while Coverage remains `unknown`; they describe saved Facts, not a proven complete season. No trend label, season comparison, WHIP, pitch-level analysis, or Mock fallback is used.

The Analysis request is made only when a canonical NPB Player's Analysis tab opens. Loading, empty and error states remain inside that tab; Profile, Recent and Game Log continue independently. MLB's existing Analysis route remains unchanged. The public Vercel route uses the existing server-side Turso read-only credential and returns only aggregate results and display identity. `Server-Timing` reports database read and aggregation duration for operations.
