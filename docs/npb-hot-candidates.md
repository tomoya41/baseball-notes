# NPB HOT candidate foundation (read-only)

HOT means identifying recent strong results by published, deterministic rules; it is not a forecast, AI opinion, or official qualification. This first engine reads the existing all-player `7d` batch result, preserving each player's period metrics, metric status, collection coverage and sample. It adds **zero DB queries**, writes no Derived rows, and does not change Home, Player, Ranking, collector, or delivery payloads. `14d`, `30d`, Rising/Cooling, season-relative change, percentile and composite scores are outside this phase.

Production candidates require `coverage.status === complete`, every metric used for ranking to be `complete`, and the sample gate below. A mathematically available metric is not sufficient when the seven calendar days lack collection proof. Excluded candidates remain in the diagnostic result with all applicable reasons: `coverage_not_complete`, `insufficient_sample`, `metric_partial`, `metric_unavailable`. This separation allows a developer to inspect an OPS of 2.000 over five PA without publishing it as HOT.

| Role | Initial sample gate | Rank order |
| --- | --- | --- |
| Batter | PA ≥ 20 | OPS descending, PA descending, HR descending, H descending, canonical Player ID ascending |
| Starter | GS ≥ 1 and outs recorded ≥ 15 | ERA ascending, K/9 descending, outs descending, BF descending, canonical ID ascending |
| Reliever | Relief appearances ≥ 2 and outs recorded ≥ 6 | ERA ascending, K/9 descending, appearances descending, outs descending, canonical ID ascending |

Thresholds are centralized in `DEFAULT_HOT_SAMPLE_POLICY` and may be overridden in a controlled diagnostic. Pitchers with incomplete GS cannot be classified and remain `unclassified_pitcher` diagnostics, never ranked. A pitcher with any start is placed in the starter group; current period pitching aggregates include all of that player's appearances, including relief work if mixed. Role-specific ERA will require a later Fact grouping extension before mixed-role rankings are interpreted as starter-only performance. HLD and SV remain display Facts and do not affect rank. **WHIP is never used** because nf3 pitching Facts do not provide standalone BB. Zero-outs and incomplete ERA/K/9 are excluded rather than converted to zero.

`rankInputs` records the exact numbers and final canonical-ID tie-break. The first `limit` eligible players are returned per role; excluded players remain in `candidates`. The production gate reports readiness separately for batter, starter and reliever and remains closed unless **all three** have at least one eligible candidate. This is a minimum safety gate, not an approved launch-size threshold. NPB-wide selection is the default. Central/Pacific filtering is supported only when verified player-to-division metadata is supplied for the entire batch; absent metadata produces an error instead of silently misclassifying players. Display name/team/position remain optional presentation metadata, outside the aggregation domain.

Run `npm run verify:npb:hot -- --date=2026-09-24` for local diagnostics. The existing **manual-only** period-batch verification Action also runs the same read-only HOT diagnostic against Turso. Both commands enforce SELECT-only SQL and compare protected table counts before/after. They report candidate count, coverage-complete count, eligible count, exclusion reasons, gate state and HOT-specific query count. No candidate list or DB credential is published. Fixture tests prove sorting, eligibility, tie-breaks, division filtering and production-gate behavior without external access.

The [manual Turso diagnostic](https://github.com/tomoya41/baseball-notes/actions/runs/36126977347) succeeded on 2026-09-25 for the 2026-09-18–24 window: 205 batter results, 77 pitcher results, 239 unique players, 244 batting Facts and 79 pitching Facts. All 282 role results had unknown collection coverage; coverage-complete and production-eligible counts were **0 in each role**. The production gate was closed. Exclusion reason counts can overlap: 282 coverage, 268 insufficient sample, 54 unavailable ranking inputs. This run used the existing six-read batch and the HOT calculation issued no extra SQL. The read-only guard and protected row-count comparison succeeded. A verified full-day unattended scheduled collector run is still pending. Recheck current Turso data before any public rollout and review whether enough comparable players meet both coverage and sample requirements. This phase does not switch Home HOT to real data.
