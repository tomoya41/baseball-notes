# 日程・結果から試合別MVPを確認する

R02/R08、J01。NPB公式戦の日程・結果と試合詳細にある既存MVP開閉枠を接続する。新規画面・画像・CSS・統計データ・Sourceは追加しない。閉じた初期表示と13–15pxの既存文字、44pxの操作領域を維持する。

## 選考とデータ境界

日別MVPは従来どおり、日付全体のCoverage completeと全終了試合の完全な選手成績が必要。日付がpartialでも、その中の一試合が独立にcompleteで、保存済みの両球団の打撃・投球成績を照合できる場合は、**その試合だけ**のMVPを既存の採点関数で選べる。日別MVPを別名で公開するものではない。NPB HOT/Rankingの最低母数・Production Gateは変更しない。

日程とキャッシュのGame ID・日付・第何試合・ホーム/ビジター・スコア・completeと各役割の利用可否を照合する。NULL、重複、違う試合・訂正スコア、欠損、未来/未終了は選考しない。failed/unknown/no_gamesの日付も対象外。CS・日本シリーズは別の既存画面・成績範囲を維持する。

成績を新規取得せず、以前開いた試合詳細の検証済み端末キャッシュだけを使用する。最大12試合、MVP枠を開いたときだけ既存の一回のキャッシュ読取を共有する。日程初期表示の追加成績API通信・DB queryは0。全試合の詳細を先回りして取得しない。未訪問端末やキャッシュがない試合では選出できない。更新・訂正の確認は未完了と表示し、現在の成績・公式表彰・新たに収録した実データとは呼ばない。

## 表示・検証

既存の「MVPを見る」を開くと日別の選考状態が表示される。選出できた試合がある場合だけ、別の「試合ごとのMVP」から対戦カード・結果→選手・試合詳細へ移動する。日付を含む既存URLとcanonical IDを保持する。別日/別snapshotの確認中に以前のMVPを残さない。

部分日付の一試合と日別保留、結果・本人・役割・null・重複・未来の境界、遅延した日付切替、初期キャッシュ読取0/展開後1回、正しい選手/試合リンクを合成fixtureで検証する。fixtureは実試合・実選手として公開しない。Androidでは既存の実日付の未収録状態、追加のGame Detail通信0、360px Light/Dark、通常/150%/200%を確認する。選出例のdomain/React fixture検証と、NPB本番の成績収録・実機の確認は別に記録する。
